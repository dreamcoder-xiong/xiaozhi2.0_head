# 视觉集成全链路 — 工作总结（第九轮，2026-07-09）

## 成果概览

九轮迭代，从零到全链路稳定：

```
用户："看看周围"
  → 云端 STT → IS_VISION_KEYWORD 命中 → vision_mode_=true
  → ① 拍照 (ESP32 OV2640, MJPEG, 帧新鲜度检查)
  → ② 识别 (minicpm-v:8b, Ollama, System Prompt 35字, num_predict=50)
  → ③ 屏幕显示 (LCD 聊天气泡, lv_obj_del_async 防崩溃)
  → ④ TTS 播报 (edge-tts → WAV → I2S ES8311, MAX_TTS_CHARS=50 安全截断)
  → ⑤ 自动回到聆听状态 ("可以说话了")
```
全链路 ~17-20s（mDNS 已关闭省 7s，推理 4-7s，TTS 2-8s）

## 关键设计决策

| 决策 | 原因 |
|------|------|
| 本地 I2S 播放，不用云端 TTS | 云端不把视觉结果当用户输入 |
| 不关音频通道 | `CloseAudioChannel` 延迟回调会清屏+断聊 |
| ~~mDNS~~ → 固定 IP | ESP32 `.local` 解析不稳，省 7s |
| 笔记本静态 IP 192.168.1.13 | DHCP 变化需重编译固件 |
| POST /tts (非 GET) | URL 编码中文太长，超 buffer_size_tx |
| /vision 同步等待 TTS 缓存 | ESP32 请求时缓存必中，消除二次等待 |
| 播放后 `SendStartListening` | 直接重入聆听，不 ToggleChatState（避免重开 WebSocket） |
| vision_mode_ 提前置位 | IS_VISION_KEYWORD 命中时立即 true，消除竞态窗口 |
| I2S 输入暂停 | 视觉 HTTP 阻塞期间 `codec->EnableInput(false)`，消除 AFE 刷屏 |
| 帧新鲜度检查 | /vision 检测 frame_age，>5s 自动强制重连 MJPEG |

## 固件改动

**`main/application.cc`** — `HandleVisionCommand()`（~第742行）：
1. `vision_mode_` 在 `OnIncomingJson` 提前置位（防竞态）
2. TWDT 超时重配为 30s（HTTP 阻塞期间喂狗）
3. `codec->EnableInput(false)` — 暂停 I2S 输入（防 AFE 刷屏）
4. GET /vision（固定 IP 192.168.1.13:8080，timeout 25s）
5. 屏幕显示答案（`lv_obj_del_async` 防 LVGL 崩溃）
6. POST /tts → 解析 WAV → I2S 分块播放（chunk 预分配复用）
7. `wav_data.swap(empty)` — 强制释放 ~255KB
8. 播放完 → `codec->EnableInput(true)` → `OpenAudioChannel` → `SendStartListening`
9. 安全网：`vision_mode_` 仍为 true 时兜底恢复

**`main/application.h`** — 新增 `HandleVisionCommand()`、`vision_mode_` 标志位

## 服务端点 (vision_server.py)

| 端点 | 方法 | 说明 |
|------|------|------|
| `/` | GET | 状态（模型、帧年龄、新鲜度、缓存） |
